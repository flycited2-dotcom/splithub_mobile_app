# SplitHub Mobile: нативное приложение по образцу мобильного сайта

Дата утверждения: 2026-06-02

## Цель

Довести установленное Expo-приложение SplitHub от технического MVP до удобной
нативной версии мобильного сайта `splithub.ru`. Приложение должно сохранить
скорость и предсказуемость нативной навигации, но перенести основные сценарии
сайта: главную страницу, полный каталог, быстрые категории, подробную карточку
товара и полноценную корзину для отправки заявки.

После первого релиза интерфейс будет дополнительно шлифоваться по результатам
тестов на реальном Android-устройстве.

## Ограничения безопасности

- Не менять поведение витрины сайта: `send.php` и `index.html`.
- Не менять цены и состав активного каталога сайта.
- Не удалять `TG_FORCE_IP`, `CURLOPT_RESOLVE` и fail-open обработку заявок сайта.
- Клиент приложения обращается только к выделенным мобильным эндпоинтам:
  `api/mobile.php`, `api/lib/*`, `api/push*.php`.
- Если приложению потребуются дополнительные данные, расширять только
  изолированный мобильный API обратно-совместимым способом.
- Источником каталога остаётся `products.js` сайта с 275 активными товарами.
  `products.json` генерируется из него, а не наоборот.
- Не выполнять прямой деплой в production. Для серверных изменений использовать
  отдельную ветку, staging и smoke-тест витрины с ожидаемым ответом
  `{"ok":true}`.

## Выбранный подход

Приложение остаётся нативным Expo-приложением. WebView и встроенный браузер для
основных экранов не используются.

Этот подход выбран вместо двух альтернатив:

1. Открывать сайт внутри приложения. Это быстрее в реализации, но пользователь
   фактически получает браузерную оболочку.
2. Сделать гибрид WebView и нативных экранов. Это сокращает часть работы, но
   создаёт неоднородную навигацию и усложняет корзину.

Нативный вариант требует больше работы, зато обеспечивает единый интерфейс,
контролируемое состояние корзины и возможность постепенно улучшать приложение.

## Навигация

Нижняя панель содержит четыре вкладки:

1. `Главная`
2. `Корзина`
3. `Заказы`
4. `Профиль`

Отдельной нижней вкладки `Каталог` нет. Полный каталог открывается с главной
кнопкой `Весь каталог`. У каталога и карточки товара есть понятный возврат назад.

## Главная

Главная повторяет структуру мобильной версии сайта и использует фирменные цвета
SplitHub:

- логотип;
- кнопки `Войти` и `Заявка`;
- четыре телефонных контакта;
- блок с позиционированием оптового каталога;
- кнопка `Загрузить прайс`;
- кнопка `Весь каталог`;
- быстрые категории каталога.

Быстрые категории включают:

- `Инвертор 7–9`
- `Инвертор 12`
- `Инвертор 18`
- `Инвертор 24–36`
- `On/Off 7–9`
- `On/Off 12`
- `On/Off 18`
- `On/Off 24–36`
- `Медная труба`
- `Расходники`
- `Полупром`
- `Кассетные`
- `Канальные`
- `Напольно-потолочные`
- `Мульти-сплит`
- `Чёрные сплиты`

Нажатие на быструю категорию открывает плоский список отфильтрованных товаров,
чтобы пользователь быстрее дошёл до нужной модели.

Кнопка `Заявка` открывает корзину. Кнопка `Войти` открывает существующий экран
авторизации. Телефоны открывают системный набор номера. `Загрузить прайс`
открывает актуальную ссылку на прайс-лист через мобильную конфигурацию.

## Полный каталог

Кнопка `Весь каталог` открывает полный каталог с поиском и структурой сайта:

- раздел оборудования;
- бренд;
- при наличии бейдж завода;
- серия;
- краткое описание серии;
- сетка карточек товаров.

Поиск фильтрует товары по бренду и модели. Быстрые фильтры каталога могут
сокращать видимый набор, но не заменяют структуру брендов и серий в полном
режиме.

Карточка товара содержит:

- фотографию;
- бренд;
- модель;
- краткое описание;
- наличие;
- цену;
- кнопку `Заказать`.

Нажатие по карточке открывает подробности. Нажатие `Заказать` сразу добавляет
товар в корзину и показывает пользователю подтверждение.

## Подробная карточка товара

Экран товара содержит:

- модель и краткое описание;
- наличие;
- крупную фотографию;
- цену;
- кнопку добавления в корзину;
- выбор количества;
- основные характеристики: BTU, площадь, компрессор, фреон;
- список преимуществ;
- системное действие возврата;
- кнопки отправки ссылки: MAX, Telegram, Email и копирование ссылки.

Показываются только характеристики и действия, для которых есть данные.
Отсутствующее поле не заменяется пустой заглушкой.

## Корзина и заявка

Корзина повторяет полезные возможности сайта:

- список выбранных товаров;
- изменение количества;
- удаление позиции;
- итоговое количество;
- итоговая стоимость;
- поле комментария;
- кнопка продолжения покупок;
- кнопка отправки заявки.

Для сплит-систем дополнительно показывается блок `Комплект монтажника` с
предложениями расходников. Позиции комплекта добавляются в общую корзину обычным
образом и участвуют в итоговой сумме.

После отправки приложение использует существующий изолированный мобильный
сценарий создания заказа. При успехе корзина очищается, пользователь видит номер
заявки и может перейти к своим заказам.

## Заказы и профиль

Существующие вкладки `Заказы` и `Профиль` сохраняются. В первой итерации их
структура остаётся простой:

- `Заказы`: список заявок, сумма, дата и статус, обновление списка, переход в
  детали заказа.
- `Профиль`: данные пользователя, настройки уведомлений, Telegram менеджера,
  звонок менеджеру, открытие прайс-листа и выход.

Текст о недоступном EAS project ID необходимо убрать после проверки текущей
конфигурации push-уведомлений: EAS project ID уже настроен для сборки.

## Компоненты приложения

Реализация должна расширить существующую структуру без крупного рефакторинга:

- `HomeScreen`: главная и быстрые категории.
- `CatalogScreen`: полный структурированный каталог или плоская выборка по
  категории.
- `ProductCard`: карточка товара с отдельным действием `Заказать`.
- `ProductDetailsScreen`: подробности, количество и отправка ссылки.
- `CartScreen`: позиции, комплект монтажника, комментарий и отправка заявки.
- `catalog` helpers: преобразование данных API в группы брендов и серий,
  фильтрация быстрых категорий и поиск.
- существующий cart reducer: единый источник состояния корзины.

Не создавать отдельное состояние корзины для главной, каталога и карточки
товара. Все точки добавления товара используют существующий cart context.

## Данные мобильного API

Для полного интерфейса клиенту нужны следующие поля товара:

- `id`, `sku`, `brand`, `brandCode`, `model`
- `group`, `series`, `factory`
- `price`, `stock`, `stockLabel`
- `descShort`, `cardBenef`, `benefits`
- `photo`
- `btu`, `area`, `compressor`, `freon`, `type`, `color`

Клиент должен корректно работать, если часть дополнительных полей отсутствует:
скрывать необязательный элемент интерфейса, а не падать.

Ссылки на прайс, телефоны и менеджера следует брать из мобильной конфигурации,
чтобы не размножать значения по экранам.

## Ошибки и состояния загрузки

- Главная открывается без ожидания каталога; переход в каталог показывает
  индикатор загрузки.
- При ошибке загрузки каталога показывается понятное сообщение и кнопка
  повторной попытки.
- Если категория не содержит товаров, показывается пустое состояние с возвратом
  к каталогу.
- Ошибка добавления локального товара в корзину не должна терять уже выбранные
  позиции.
- При ошибке отправки заявки корзина сохраняется, чтобы пользователь мог
  повторить отправку.
- При изменении серверного каталога мобильный API возвращает понятную ошибку;
  приложение предлагает обновить каталог и не очищает корзину автоматически.

## Проверка

До подготовки новой APK-сборки выполнить:

1. Unit-тесты фильтрации быстрых категорий и поиска.
2. Unit-тесты группировки полного каталога по брендам и сериям.
3. Unit-тесты корзины: добавление, количество, удаление, расходники и очистка
   только после успешной заявки.
4. Проверку TypeScript, lint и существующие тесты приложения.
5. Ручной сценарий на Android: главная -> категория -> товар -> корзина ->
   комплект монтажника -> комментарий -> отправка заявки -> список заказов.
6. Ручной сценарий на Android: главная -> весь каталог -> бренд -> серия ->
   карточка товара -> отправка ссылки.

Если потребуется серверное расширение мобильного API, до любого production
деплоя дополнительно выполнить staging-тесты и smoke-тест заявки живой витрины
через `send.php`, ожидая `{"ok":true}`.

## Порядок реализации

Работа выполняется последовательно, чтобы каждую часть можно было проверить:

1. Данные каталога и тестируемые helpers.
2. Главная и навигация.
3. Полный каталог, быстрые категории и карточки товаров.
4. Подробная карточка товара.
5. Полная корзина и комплект монтажника.
6. Проверка профиля, push-конфигурации и регрессионные тесты.
7. Новая Android APK-сборка для пользовательской шлифовки.

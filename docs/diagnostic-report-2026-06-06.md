### 🔴 Находка устройства: сбой регистрации push

На экране Профиля показано: **«Не удалось подключить push-уведомления. Проверьте разрешение уведомлений и подключение.»**

- `projectId` в `app.json` задан, значит причина — сбой `getExpoPushTokenAsync`: обычно это **отсутствие FCM-креденшелов** (Firebase Cloud Messaging) в EAS-сборке и/или невыданное runtime-разрешение `POST_NOTIFICATIONS`.
- Хардненинг `a67a1bf` меняет *когда/как* вызывается регистрация, но использует тот же `getExpoPushTokenAsync` → **этот сбой сохранится и после `a67a1bf`, пока не настроен FCM**. Потенциальный блокер фичи push к релизу.
- Для разработчика: загрузить FCM V1 service-account ключ в EAS credentials + `google-services.json`, пересобрать и перетестить push на устройстве (доставку всех трёх типов).

## B. Выполнено разработчиком (фикс `a67a1bf`, проверено по коду)

> Проверка проводилась чтением фактического кода, а не по сообщению коммита.

### P0 — закрыто ✅

1. **Сетевой слой устойчив** — `src/lib/api.ts`
   - таймаут 15 c через `AbortController` (корректная композиция с внешним `init.signal`);
   - `readResponseData` читает текст и оборачивает `JSON.parse` в try/catch → не-JSON ответ 5xx даёт код `HTTP_xxx` / `INVALID_JSON_RESPONSE`, а не сырой `SyntaxError`;
   - `401 → SESSION_EXPIRED` **с автоочисткой токена**; таймаут → `REQUEST_TIMEOUT`, сеть → `NETWORK_ERROR`;
   - тесты `__tests__/api.test.ts` расширены под все сценарии.

2. **Push-слой собран до конца** — `register-device.ts`, `app/_layout.tsx`, `session-context.tsx`
   - регистрация устройства привязана к **сессии** (после login / register / восстановления профиля), а не к заходу на вкладку «Профиль»;
   - токен устройства **персистится** в AsyncStorage (`ensureDeviceRegistered` — регистрация один раз; `removeRegisteredDevice` при logout по сохранённому токену);
   - добавлен `Notifications.setNotificationHandler` → баннеры на переднем плане показываются;
   - настройки уведомлений **загружаются с сервера** (`loadNotificationPreferences` + `normalizePreferences`);
   - push-сбой обёрнут в try/catch и не блокирует авторизацию;
   - новый тест `__tests__/session-push-registration.test.tsx`.

3. **Истечение сессии больше не маскируется** — `session-errors.ts`
   - `SESSION_EXPIRED` → «Сессия истекла. Войдите заново.» вместо «Проверьте подключение к интернету».

### P1 — закрыто ✅

4. **Кэш каталога защищён** — `src/lib/storage.ts`
   - конверт со `schemaVersion` + TTL 24 ч, `safeParse`, валидация формы (`isCatalogSnapshot` / `isCatalogEnvelope`), обратная совместимость со старым форматом;
   - новый тест `__tests__/storage.test.ts`.

### Безопасность — закрыто ✅

5. **Открытие произвольного URL из push** — `notification-router.ts`: `trustedManagerUrl` с вайтлистом `t.me` / `splithub.ru` / `www.splithub.ru`, только `https`, fallback на дефолт; security-кейс покрыт тестом.
6. **`.env` добавлен в `.gitignore`.**

**Итог:** 6 из 6 код-замечаний P0 и кодовой части безопасности закрыты. Качество фиксов высокое — учтены edge-cases (внешний signal, обратная совместимость кэша, неблокирующий push).
